## Security and ranked hardening already merged

### PR #1 — verified auth and server-authoritative rank

Merged to `main` with merge commit:

`d3abd0c366fdbba754a59013459854e408cfc872`

Implemented:

- Firebase ID tokens are cryptographically verified on the backend using Google Secure Token certificates.
- Production rejects development/test auth tokens.
- Matchmaking and private-room entry require verified Firebase identity.
- Public reconnect requires the server-issued match session token.
- Client-side Elo/stat writes were removed.
- Human-vs-human Elo/stat updates are calculated by the backend.
- Ranked updates plus immutable `match_history` creation are sent atomically through Firestore REST using backend service-account credentials.
- Ranked persistence is idempotent per game instance and duplicate history creation is protected with a Firestore create precondition.
- Bot fallback matches remain intentionally unranked.
- Firestore rules prevent clients from editing ranked fields.
- `.github/workflows/quality.yml` runs `npm ci`, `npm test`, `npm run test:auth`, `npm run check:assets`, and `npm run build`.

PR #1 Quality Gate and the post-merge `main` Quality Gate both passed.

### PR #2 — reconnect and PIN hardening

Merged to `main` with merge commit:

`5cc442c4d323051316fb272a70fa2ff39c7d61cd`

Implemented in `server/room-manager.ts`:

- Removed the lower-level reconnect-by-color fallback entirely.
- `handleReconnect` now requires a session token.
- Private-room PIN generation now uses `crypto.randomInt(100000, 1000000)` instead of `Math.random()`.
- Unique PIN generation fails explicitly after 100 unsuccessful attempts.

PR #2 Quality Gate and the post-merge `main` Quality Gate passed.

### PR #6 — ranked persistence uses the same named Firestore database as the frontend

Merged to `main` with merge commit:

`a93d8d79d518c8830966992af8132fe8a687a3a6`

The database-ID risk was confirmed as a real bug:

- `src/lib/firebase.ts` initializes Firestore with `getFirestore(app, FIRESTORE_DATABASE_ID)`.
- `firebase-applet-config.json` sets `firestoreDatabaseId` to `ai-studio-oukkhmeronline-bf9c8f38-eb74-4b5e-bcbd-efb1abfaeebc`.
- The pre-PR #6 backend `server/ranked-manager.ts` hardcoded Firestore REST reads/writes to `(default)`.

PR #6 changed authoritative ranked persistence so all user reads, document resource names, and commit requests target the named database. The backend accepts an optional `FIRESTORE_DATABASE_ID` environment override and otherwise falls back to the exact current production database ID above. This means a new Railway variable is not required for the current deployment, although setting it explicitly later is reasonable for configuration clarity.

PR #6 Quality Gate passed before merge. The post-merge `main` Quality Gate also passed all steps: core engine tests, auth security regression tests, asset integrity, and production build.

The remaining ranked verification is a real two-account human-vs-human match after the backend running on Railway contains the PR #6 commit. ### PR #4 — restore assets and sync AI check splash

Merged to `main` with merge commit:

`0dc7dda933b315f0d189101d6949dcebab10b4ad`

Problem found after PR #3:

- A catch-all Vercel rewrite sent requests such as `/assets/...` to `/index.html`.
- The page itself loaded, but bundled images such as the mascot/logo were broken because asset requests were rewritten to HTML.

PR #4 changed `vercel.json` from a catch-all SPA rewrite to explicit app-route rewrites (`/home`, `/play`, `/online`, `/leaderboard`, `/settings`, `/history`, `/tactics`) so `/assets/*` and `/pieces/*` remain real static files.

The same PR also fixed the Khmer check splash animation used by `ChessBoard`:

- Existing 1v1/local and online modes already showed the large Khmer `អុក` calligraphy splash when a king is in check.
- AI could immediately make its reply move and clear the check state, which caused the splash to disappear/cancel before it was visible.
- The splash logic was changed to be event-based so an AI response cannot immediately cancel the 3-second check animation.

The PR branch was verified with:

- `npm test`
- `npm run test:auth`
- `npm run check:assets`
- `npm run build`

The resulting `main` Vercel production deployment for commit `0dc7dda...` reached `READY`, and the build output contained hashed frontend assets including the mascot and app bundle.

## Firestore rules currently deployed

The deployed/source rule intent is:

- `/users/{uid}` remains public-readable for existing leaderboard compatibility.
- owners may create/update their own profile but cannot change ranked fields (`rating`, `peakRating`, `wins`, `losses`, `draws`, `winStreak`, `gamesPlayed`).
- `match_history` can be read by authenticated users but cannot be written by clients.
- everything else is denied by default.

The public/private profile split is intentionally deferred because the current leaderboard reads `/users` directly. Do not mix that migration into unrelated bug fixes.

## Domain / DNSSEC status

TenTen DNS is currently configured with:

- host: `ouk`
- type: `CNAME`
- target: `cname.vercel-dns.com`

Keep that CNAME. The Vercel certificate failure was not caused by the CNAME itself.

Vercel reported DNSSEC validation failure for `ouk.kuonkhmer.com`, specifically `DNSKEY Missing` / invalid DNSSEC delegation for `kuonkhmer.com`. The user is waiting for TenTen support to remove the stale/invalid DS state at the `.com` registry.

Suggested support wording already given to TenTen:

> kuonkhmer.com hiện có DNSSEC delegation/DS không hợp lệ. Public validation báo DNSKEY Missing mặc dù tôi không sử dụng DNSSEC. Vui lòng xóa toàn bộ DS record của kuonkhmer.com tại .COM registry, không phải kích hoạt dịch vụ DNSSEC.

Do not repeatedly remove/re-add the Vercel domain and do not tell the user to change the `ouk -> cname.vercel-dns.com` record while the DNSSEC issue is unresolved.

If moving DNS to Cloudflare later, remove/fix the stale registrar DS first, then migrate nameservers, create the `ouk` CNAME, and only enable DNSSEC after Cloudflare is active and the new DS can be published correctly.
